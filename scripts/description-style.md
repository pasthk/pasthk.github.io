# description 寫作規格

全站每個對外收錄的頁面都要有 `frontmatter.description`。它以同一個字串供應五個出口：

1. `<meta name="description">` 與 `og:description`（搜尋結果、社群分享）
2. `og/*.png` 卡片第二行
3. `llms.txt` 條目簡述
4. 搜尋索引的自訂關鍵詞（權重高於正文）
5. `page-index` 的欄位

改動後執行 `npm run docs:desc` 檢查，建置時的 `checks.ts` 亦會提示缺漏。

## 一、共通規則

| 項目 | 規則 |
| --- | --- |
| 語言 | 繁體中文書面語；不用「您／我們」，不自稱「本頁」「本文」 |
| 長度 | 40–150 字；以 80–110 字最理想（超過 155 字會被搜尋結果截斷） |
| 標點 | 全形；只以「。」結尾；不用省略號、不用半角逗號冒號 |
| 書名 | 報刊、法例、文獻標題用《》；篇名用〈〉；引語用「」 |
| 年份 | 「YYYY年M月D日」；範圍用「YYYY年至YYYY年」，不用半角連字號 |
| 空格 | 中文之間不留空格；英文詞與中文之間留一個半形空格 |
| 開頭 | 以主題名開頭（索引頁）或刊名開頭（史料頁），不重述整句標題 |
| 重複 | 不同頁面不得共用同一段 description |

## 二、史料頁（有 `datePublished`）

句式：`《刊名》YYYY年M月D日 + 動詞 + 事件要點。`

- 動詞按材料性質選用：報道、刊出、載、介紹、披露、專訪。
- 刊名後直接接日期，不加「在」「於」。
- 事件要點寫具體：人物、地點、數字、結果；避免「有關」「相關」等虛詞。
- 篇幅一句至兩句，落在 60–120 字。原文為文言或 OCR 者亦改寫為現代書面語，不照抄。

例：

> 《大公報》1955年8月10日報道深水埗李鄭屋村建築工地發現拱形古墓，掘出10件陶器移交香港大學研究，林仰山教授推測墓葬年代或在漢唐之間。

## 三、索引頁（無 `datePublished`）

句式：`{主題}文獻索引，收錄{年份範圍}{主要報刊}{數量}，記錄{內容面向}。`

- 材料類型寫清楚：文獻索引（含檔案、報告、論著）／報道索引（以報刊為主）。
- 盡量交代實際收錄量：年份跨度、主要報刊名、篇數或碑刻數。沒有資料的頁面用「現收錄……」表示範圍有限。
- 「記錄」「整理」「涵蓋」後接 2–3 個具體面向，不用「相關史料」「各種記錄」泛稱。
- 站務頁（關於、隱私、支持）以「香港文獻類編的……」開頭，說明頁面內容。

例：

> 西貢沙下遺址文獻索引，收錄2000年至2007年《中國文物報》《考古與文物》的發掘簡報與研究論著、古物古蹟辦事處調查報告，以及文物探知館的展覽記錄。

## 四、檢查項目

`scripts/check-descriptions.mjs` 針對下列項目把關：

- 錯誤：缺 description、未以「。」結尾、半角標點、史料頁開頭格式不符
- 提醒：過短（<35 字）、過長（>155 字）、連續空白、引號不成對、以標點開頭、自稱「本頁」、跨頁重複

`index: false`／`sitemap: false` 的導覽殼頁不在檢查範圍，但補寫描述仍是好習慣。
