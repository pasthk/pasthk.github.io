## 二、P0：直接阻礙收錄與排名的問題

### 1. 38 個空殼頁面上線（最優先）— ✅ 已處理（2026-10-31）

> **處理結果**：38 頁原本已有 `index: false`，但該欄位在本技術棧無效（`@vuepress/plugin-sitemap` 只認 `sitemap: false` 與 `robots: noindex`；`index` 僅由搜尋外掛消費，而本專案未安裝搜尋外掛）。已為 38 頁補上 `sitemap: false` 與 `head` 的 `robots: noindex`。建置驗證：sitemap 由 235 條降至 **197 條**（正好減 38），38 頁均輸出 `<meta name="robots" content="noindex">`，正常頁面未受影響。

以下頁面只有一個 `## 新聞報道` 標題，正文 0 字，但已部署、已在站內導航：

```
src/tropical-cyclone/1954-signal.md ～ 1990-signal.md   （37 頁）
src/custom/mid-autumn-festival.md
src/education/chung-chi-college.md
src/legislation/cap-53/19711029-cap-53.md
```

**為何致命**：這是 Google 判定「低品質/未完成網站」最直接的訊號，且會拖累整個網域的品質評分，不只是這 38 頁。

**修法**（二選一）：
- 有資料的年份 → 補上條目；暫時沒資料的 → 在 frontmatter 加 `index: false`（theme-hope 會排除建置），或整檔移出 `src/`。
- 若想保留「年份骨架」供未來擴充，改為在上一層目錄頁列出「尚在整理」的年份，不要各自獨立成頁。

### 2. 84 處「無名 No Name」佔位標題被索引

例：`src/tropical-cyclone/1932-signal.md` 的 `## 無名 No Name 1` ~ `## 無名 No Name 6` 直接渲染成 `<h2>` 進 HTML。

**修法**：這是可批次處理的。建議規則 `YYYY年M月D日：<該日首篇報道標題>`，或 `<報刊>報道：<事件>`。例如：

```
## 無名 No Name 3
→ ## 1932年7月21–23日：七號風球、臨馬島貨艇沉沒
```

批次腳本可依 `## 無名 No Name N` 段落內第一條 `〈...〉` 的篇名自動生成，再人工潤飾。

### 3. 30 個目錄頁完全隱形

`/archaeology/`、`/tropical-cyclone/`、`/tropical-cyclone/1930s/`、`/public-health/`、`/education/` … 共 30 頁，同時具備四個問題：

| 問題 | 實測 |
|---|---|
| 不在 sitemap | `sitemap.xml` 只有 235 條，不含任何目錄頁 |
| 零內部入鏈 | 全站沒有任何 `<a>` 指向它們 |
| 標題是英文 | `Archaeology`、`Public Health`、`Tropical Cyclone`、`1890s` |
| description 重複 | 全部 = 「認識香港，從文獻開始。」 |
| 正文極短 | 平均 302 字元，內容只有一個目錄清單 |

**這些本應是最大的流量入口**——「香港考古」「香港颱風歷史」「1890年代香港」這類查詢的落點就是它們，但目前搜尋引擎根本看不到。

**修法**：
1. 為每個目錄建立 `README.md`（或 `index.md`），寫 800–1500 字導言：定義、時間跨度、收錄範圍、資料來源、如何使用本索引。
2. 中文標題，帶關鍵詞：
   - `Archaeology` → `香港考古`
   - `Tropical Cyclone` → `香港熱帶氣旋與風球紀錄`
   - `1890s` → `1890年代香港風球紀錄`
   - `Public Health` → `香港公共衛生史`
3. 導航（navbar）加入章節入口，或首頁加入「主題」區塊——目前 navbar 只有「閱讀說明 / 本站資訊 / 項目」三項，首頁只有 5 條站內連結，等於沒有任何通往內容的路。

### 4. 單篇轉錄頁是死胡同

120 篇轉錄頁（如 `/tropical-cyclone/1930s/19320518-the-kung-sheung-evening-news-p3.html`）的站內連結只有 **5 條，全部來自導航**：

```
/  /about.html  /project/ay1928/  /reading-notes.html  /support.html
```

沒有回到父事件頁、沒有同期兄弟報道、沒有上級目錄。權重在此斷流，讀者也無路可走。

**修法**：在頁尾自動加三組連結（可用 theme-hope 的 `prev`/`next`，或自訂 layout）：
- **所屬事件**：回父頁（如「1932年風球紀錄」）
- **同期報道**：同月/同事件的其他報刊篇目
- **上一則 / 下一則**：同目錄依日期排序

目標：每頁 8–12 條語義內鏈（目前 9.4 條但幾乎全是樣板）。

### 5. description 與 title 重複

- 31 頁共用「認識香港，從文獻開始。」
- 10 組重複 title，最嚴重的是 `論著`（4 頁）、`報告`（4 頁）、`圖錄`（2 頁），以及多組報紙標題重複（`一號風球已除下`、`颶風已向海南島吹去` 等，因同一標題在不同日期重複見報）。

**修法**：
- 目錄頁 description 自動生成：`收錄 1897–1899 年共 N 篇《香港華字日報》風球報道，含篇名、版次與原文轉錄。`
- `論著`/`報告`/`圖錄` 改為帶主題的標題：`殷墟發掘報告索引`、`曹操高陵研究論著`。
- 重複見報標題加報刊與日期後綴：`一號風球已除下（《工商晚報》1932-05-18）`。

## 三、P1：內容策略

### 6. 全站零圖片 — 最大的未開發流量

235 個檔案、268 個頁面，**0 張內容圖片**（只有 7 個收款 QR code SVG）。

歷史文獻站沒有原報紙圖像，等於：
- 完全放棄 Google 圖片搜尋（對「舊報紙」「歷史照片」類查詢是巨大流量池）
- 頁面停留時間、E-E-A-T（一手史料佐證）都偏弱
- `og:image` 只能指向 268×268 的 favicon，社群分享無預覽圖

**修法**：
- 每篇轉錄頁配 1 張原報紙剪報圖（局部或縮圖），`alt` 寫成 `《工商晚報》1932年5月18日第3版：一號風球已除下`。
- 同一張圖同時作為該頁 `og:image`（需 ≥1200px 寬，才符合 Google 文章 rich result 要求）。
- 版權處理：用縮圖／局部並標明來源，與現有「資料使用」聲明一致。

### 7. 薄頁不要刪，要「加值」

146 頁正文 <600 字元。轉錄頁的價值不在字數，而在**解說**。

**修法**：每篇加 100–200 字編者按，回答四個問題：
1. 這篇報道說了什麼（一句話摘要）
2. 與前後報道的關係（事件脈絡中的位置）
3. 史料價值（為何值得保留：獨有細節？數據？術語？）
4. 可對照的其他報刊

這樣一篇 300 字的轉錄會變成 500–600 字有獨立價值的史料頁，且每頁都有獨特文字，解決重複內容問題。

### 8. 同事件多報刊的重複內容

`19320518 工商晚報` 與 `19320519 工商日報` 兩篇幾乎同文（同一事件的隔日報道）。目前兩頁各自獨立、標題相同。

**修法**：以一篇為主（設 canonical），其餘在頁內以「異文對照」呈現；或在事件頁用表格並列不同報刊的措辭差異——這反而是學術價值所在。

### 9. 主題權威被稀釋

`/project/ay1928/` 是河南安陽考古（殷墟、甲骨、曹操高陵、洹北商城），17 頁、占全站 7%，與「香港文獻」無主題關聯。

**修法**：獨立子網域或獨立 repo；若必須同站，至少 `noindex` 並排除於主 sitemap，避免干擾「香港歷史」的主題集中度。

### 10. 首頁標題是「前言」

`<title>前言 | 香港文獻類編</title>`，`<h1>前言</h1>`。

**修法**：
```
title: 香港文獻類編｜香港舊報紙與歷史文獻索引
h1: 香港文獻類編
```
首頁是品牌詞 + 核心詞的唯一落點，不該浪費在「前言」上。

## 四、P2：技術與結構化資料

### 11. 結構化資料過於單薄

目前每頁只有：

```json
{"@type":"Article","headline":"...","image":["https://www.pasthk.com/favicon.png"],
 "datePublished":"1932-05-18","dateModified":"...","author":[...]}
```

缺：
- `BreadcrumbList`（可出麵包屑 rich result，且強化層級理解）
- `WebSite` + `SearchAction`
- `Organization` / `Person`（作者實體）
- `isPartOf`（連回所屬事件與章節）
- `image` 指向 favicon（268×268）→ **完全拿不到文章 rich result**

**修法**：在 `theme.ts` 的 `jsonLd` 回調改用 `@graph` 一次輸出多個實體：

```ts
jsonLd: (jsonLd, page) => {
  const fm = page.frontmatter as Record<string, string | undefined>;
  return {
    "@context": "https://schema.org",
    "@graph": [
      { ...jsonLd, "@type": "Article",
        image: fm.image ? [`${hostname}${fm.image}`] : undefined,
        isPartOf: { "@type": "WebSite", name: "香港文獻類編", url: hostname } },
      { "@type": "BreadcrumbList", itemListElement: /* 由 page.path 拆層 */ },
    ],
  };
},
```

同時 `ogp` 回調加上每頁 `og:image`。

### 12. 沒有站內搜尋

`theme.ts` 的 `plugins` 內沒有任何 search 外掛（但 `public/` 有 `algolia-site-verification.html`，說明曾申請過）。235 頁的檔案站沒有搜尋，使用者只能靠側邊欄逐層點。

**修法**：theme-hope 內建 `slimsearch`，零外部依賴、零成本：

```ts
plugins: {
  slimsearch: { indexContent: true },
  // ...
}
```

同時滿足 `SearchAction` schema 的實際功能要求。

### 13. 提交管道偏向百度，缺 Google / Bing

`.github/workflows/deploy-docs.yml` 有「Collect new URLs for Baidu」主動推送，但：
- 沒有 Google Search Console 驗證與 sitemap 提交
- 沒有 IndexNow（Bing / Yandex / Naver，免費、一次 HTTP POST）
- 沒有 Bing Webmaster Tools

受眾在香港，Google 市佔壓倒性。百度推送的優先級應低於 GSC。

**建議**：加 IndexNow（改動最小：部署後 POST 新 URL 清單到 `https://api.indexnow.org/indexnow`），並在 GSC 提交 sitemap。

### 14. sitemap 所有 URL 都是 `changefreq=daily`

包含 1902 年的史料頁。這是噪音，會降低 sitemap 可信度。

**修法**：按頁型設定——事件頁 `monthly`、轉錄頁 `yearly`、首頁 `weekly`；並確認 `lastmod` 反映真實修改時間（目前看起來是 git commit 時間，尚可接受）。

### 15. 沒有分析工具（盲飛）

`about.md` 明言「沒有安裝 Google Analytics 或其他分析服務」。這意味著所有 SEO 改動都無法驗證效果。

**建議**：至少裝 Cloudflare Web Analytics（免費、無 cookie、與現有隱私政策相容），或 GA4。同時開通 GSC——GSC 的曝光/點擊/平均排名是唯一可信的 SEO 儀表板。
